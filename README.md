# dev-rules

어떤 프로젝트에 넣어도 개발 결과물의 품질이 좋아지도록 만든 공통 개발 규칙 문서 모음입니다.
사람과 AI 코딩 도구(Claude Code 등)가 같은 기준으로 생각하고, 작게 바꾸고, 검증까지 하도록 돕는 것이 목적입니다.
특정 회사나 도메인의 규칙은 넣지 않습니다.

## 파일

| 파일 | 내용 |
|---|---|
| [CLAUDE.md](CLAUDE.md) | 진입점. AI 행동 지침, 문서 역할, 프로젝트 개요·빌드·브랜치 템플릿 |
| [GOAL.md](GOAL.md) | 목표와 품질 우선순위, 의사결정 기준, 비목표, 완료 기준 |
| [RULE.md](RULE.md) | 강제 코드 규칙. 계층과 책임, 데이터 객체, 트랜잭션과 외부 호출, 에러 처리, 로깅, 주석, 이름, 검증, 금지 목록 |

## 쓰는 법

1. 세 파일을 프로젝트 루트에 복사합니다.
2. `{ }`로 표시한 부분을 프로젝트에 맞게 채웁니다.
3. 맞지 않는 절은 지우고, 영역별 세부 규칙이 필요하면 `RULE.{영역}.md`를 추가합니다.
4. Claude Code는 `CLAUDE.md`를 자동으로 읽습니다. 다른 도구는 시작할 때 세 파일을 읽게 합니다.

## 기준

- 언어와 프레임워크에 상관없이 쓸 수 있는 규칙만 담았습니다. 특정 스택 전용 규칙(어노테이션, ORM 설정, SQL 매퍼 등)은 넣지 않습니다.
- 스택 전용 규칙이 필요하면 프로젝트에서 `RULE.{스택}.md`를 따로 만들어 씁니다.
- 외부 API와 DB를 함께 다루는 기능의 트랜잭션 분리(Phase 패턴), 중복 방지, 식별 로그, 외부 연동 로그 규칙을 중심에 둡니다.
